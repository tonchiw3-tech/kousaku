1ER図

予約・スタッフ情報の論理構成

MySQLに予約情報、完了後の訂正履歴、スタッフ認証情報を保存する。訂正履歴は予約ごとに複数件を保存し、reservation_status_corrections.reservation_idを外部キーとしてreservations.idを参照する。予約とスタッフ情報の直接の外部キー関係は設けない。

4初期データ

MySQL 8系 CREATE TABLE
CREATE TABLE reservations (
  id BIGINT NOT NULL AUTO_INCREMENT, reservation_number VARCHAR(30) NOT NULL,
  reservation_date DATE NOT NULL, reservation_time TIME NOT NULL, participants INT NOT NULL,
  customer_name VARCHAR(100) NOT NULL, email VARCHAR(254) NOT NULL, age_group VARCHAR(20) NOT NULL,
  visit_type VARCHAR(10) NOT NULL, unit_price DECIMAL(10,0) NOT NULL, total_price DECIMAL(10,0) NOT NULL,
  status VARCHAR(20) NOT NULL DEFAULT 'RECEIVED',
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (id), UNIQUE KEY uk_reservations_number (reservation_number),
  KEY idx_reservations_schedule (reservation_date, reservation_time),
  CONSTRAINT chk_participants CHECK (participants >= 1),
  CONSTRAINT chk_visit_type CHECK (visit_type IN ('FIRST','REPEAT')),
  CONSTRAINT chk_status CHECK (status IN ('RECEIVED','CONFIRMED','READY','COMPLETED','CANCELED'))
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE reservation_status_corrections (
  id BIGINT NOT NULL AUTO_INCREMENT, reservation_id BIGINT NOT NULL,
  before_status VARCHAR(20) NOT NULL, after_status VARCHAR(20) NOT NULL,
  changed_at DATETIME NOT NULL, operator_username VARCHAR(100) NOT NULL, reason VARCHAR(1000) NOT NULL,
  PRIMARY KEY (id), KEY idx_corrections_reservation (reservation_id, changed_at),
  CONSTRAINT fk_corrections_reservation FOREIGN KEY (reservation_id) REFERENCES reservations(id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE staff_users (
  id BIGINT NOT NULL AUTO_INCREMENT, login_id VARCHAR(50) NOT NULL,
  password_hash VARCHAR(255) NOT NULL, role VARCHAR(30) NOT NULL DEFAULT 'STAFF',
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (id), UNIQUE KEY uk_staff_users_login_id (login_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

6まとめ

DOCUMENT 08 Ver 1.1では、DOCUMENT 07のSpring Boot・MyBatis・MySQL構成に合わせ、予約情報、完了後の訂正履歴、スタッフ情報を定義した。予約ステータスはRECEIVED、CONFIRMED、READY、COMPLETED、CANCELEDの5種類とする。

完了後の訂正はCOMPLETEDからREADYへ戻す場合に限り、予約の更新と訂正履歴登録を同一トランザクションで実行する。キャンセルはステータス更新で予約データを保持し、物理削除は認証済みスタッフが確認操作を行った場合に限る。

7実装照合結果（2026年10月21日）

実装済みテーブル：reservations、reservation_status_corrections、inquiries。staff_usersはschema.sqlおよびMyBatis Mapperに存在しない未実装テーブルであり、本書の旧設計記載は実装済みとして扱わない。スタッフ認証は環境変数を用いたSpring Securityのインメモリーユーザーで実装している。

schema.sqlとの一致：reservationsには予約番号UNIQUE、日付・時刻複合INDEX、人数・利用区分・5種類の予約ステータス（RECEIVED / CONFIRMED / READY / COMPLETED / CANCELED）のCHECK制約がある。訂正履歴はreservations.idへの外部キーと複合INDEXを持つ。inquiriesには問い合わせ番号UNIQUE、状態・作成日時複合INDEX、カテゴリ・状態CHECK制約がある。

Mapperとの一致：ReservationMapper（INSERT / SELECT / UPDATE / DELETE）、ReservationCorrectionMapper（INSERT）、InquiryMapper（INSERT / SELECT / UPDATE）を使用する。実行用schema.sqlは初期INSERTを含まないため、本書のテスト用INSERTは学習用の例としてのみ扱う。
